Capture-privacy experiment

Experiment 2 — auto-hide the on-page overlay during a screen share this page starts itself, and restore it when the share ends.

1 · Get your two proof recordings

Do this twice. Each run records your screen share to a .webm file you can download, play back, and submit.

Run A — baseline: leave the box below unchecked. The AgentFury overlay stays visible, so it appears in the video → proof it does get captured.
Run B — auto-hide: check the box. The overlay is removed the moment capture starts, so it's absent from the video → proof the privacy feature removes it.
Capture: idle  ·  Privacy mode: off
When Chrome's picker appears, choose Entire Screen (or the specific window/tab that has the AgentFury overlay) so the overlay is inside the recorded region. Then select some text on that page to make the bar appear while recording.

2 · What this proves — and what it can't

  • This works because the share is started here, with getDisplayMedia(). A page can observe a capture it initiated — the returned MediaStreamTrack fires ended when the user stops sharing. That's the whole lifecycle this experiment rides on.
  • It does not hide the overlay from the recording pixels. It removes the overlay, so there is nothing to capture. The features are off while it's hidden. Nothing in a browser can keep a rendered element visible to you but absent from a recording.
  • It cannot detect an external recorder (OBS, Windows Game Bar, QuickTime, a proctoring client). Those never call this page's getDisplayMedia, and no browser API reports capture started by another application. So the trigger simply never fires for them.

That last point is the boundary: auto-hide only works for a share you start through a cooperating surface. It is a privacy convenience, not a way to be covert against monitoring you didn't initiate.
