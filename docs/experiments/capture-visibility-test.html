2 · Can this page detect that it is being recorded?

Self-initiated capture: not started
External recorder (OBS, Win+G, QuickTime, Meet/Zoom share): undetectable — no API exists
A page can observe only the MediaStream it obtained itself via getDisplayMedia(). There is no event, permission, or property that reports capture started by another application, because exposing that would itself be a fingerprinting and anti-analysis vector.

4 · Expected result

All of A–H appear in every capture type. None of the rendering techniques affects capture, because each one is an input to compositing, and capture samples the framebuffer after compositing. Shadow DOM, iframes, canvas, z-index and GPU layer promotion change how pixels are produced and how the DOM is structured — not whether the resulting pixels exist.

The one row that differs is the last column. Browser UI outside the page viewport — tab strip, address bar, extension side panel — is absent under Tab capture and present under Window and Screen capture. That is not concealment: the surface was simply never inside the captured region.

Capture exclusion does exist, but not for web content. Windows exposes SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE) and macOS exposes NSWindow.sharingType = .none. Both take a native window handle, so they are reachable only from a desktop application, never from page or extension JavaScript. This is deliberate: an overlay that a victim sees but a screen-share does not is a phishing primitive, so the platform withholds it from web content and grants it to password managers and DRM playback.
